# ARKI-K8 to K11 — Consolidated Final Report

## Executive result

**K8–K11 = PASS_WITH_OBSERVATIONS.** The controlled knowledge program now proves a complete bounded path from three real public sources to source-derived claims, human validation, logical storage separation, deterministic retrieval, specialist interpretation and multi-perspective synthesis.

The implementation does not claim autonomous architectural authorship. It does not create a decision, recommendation, winner, geometry mutation, compliance conclusion or measured performance result.

## K8 — Real-source pilot

Three sources were registered with stable IDs, public provenance URLs, bounded content units and source locations:

| Source | Primary role | Epistemic result |
|---|---|---|
| ARB Architects Code 2025 | Professional practice and judgment | Source statement, context-bounded |
| American Solar Energy Society passive-solar article | Bioclimatic and housing strategy | Strategy candidate, context-bounded |
| Peru RNE publication | Regulatory intelligence | Regulatory source statement, context-bounded |

Rights are stored as `UNKNOWN`; public accessibility is not treated as a license. Only bounded metadata, short content units and paraphrased claims are retained.

## K9 — Validation and applicability

K9 proves the complete human lifecycle: candidate, corrected, confirmed, context-limited, rejected and superseded. Original claims remain preserved after correction. Contradictions remain visible and do not produce a winner. K4 eligibility is explicit: confirmed, corrected and context-limited claims may be retrieved; rejected and superseded claims are excluded.

## K10 — Storage architecture

K10 defines three logically separate source-of-truth roles: `SOURCE_STORE`, `KNOWLEDGE_STORE` and `PROJECT_EXPERIENCE_STORE`. The client reads through K4. Local caching is optional and non-authoritative. Production persistence, vector databases, embeddings and RAG remain deferred. No second identity system was created.

## K11 — Deep specialist pilot

The controlled HOUSE-A21 question is processed through Housing and Bioclimatic perspectives. K4 retrieves the ASES source in project context without fabricating a project trace. K6 produces bounded interpretations. K7 preserves the resulting tension/trade-off and returns a provisional implication for the human architect. Source traceback reaches the source ID, content-unit ID and source location.

The pilot does not choose a plan, assert passive performance, mutate geometry or issue regulatory compliance. `HUMAN_ARCHITECT_FINAL` remains the authority boundary.

## Reuse and change surface

The implementation reuses K3 source provenance, K4 structured retrieval, K5 need assessment, K6 controlled perspectives and K7 synthesis. The only existing-surface change is K4 project-context retrieval: a source-derived record may remain eligible when the query requests unknown context explicitly, while project experience records still require a matching `projectTrace`.

## Validation evidence

The focused K1–K11 regression run passed **75 tests across 10 files**. The complete Web suite passed **414 tests across 80 files**. TypeScript passed. Production build passed after transforming 2,475 modules. `git diff --check` passed.

The build emitted existing warnings about large chunks and the test environment emitted existing canvas/Three.js warnings; neither caused a failure. No new dependency was introduced.

## Explicit non-claims

This order does not activate general knowledge federation, unrestricted Internet learning, automated source licensing, autonomous design, final architectural judgment, regulatory compliance certification, thermal or airflow simulation, geometric synthesis, or production persistence.
