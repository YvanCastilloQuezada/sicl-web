# MANUAL DE FORMAS ARQUITECTÓNICAS — ARKI

**Estado:** CHECKPOINT / MINIMAL IMPLEMENTATION

Este Manual es un **corpus de conocimiento separado dentro del repositorio ARKI**, pero utiliza el mismo motor de razonamiento, provenance, DesignMemory, transferencia, gates de aprendizaje y CanonicalBuildingModel. No es un producto, motor ni sistema de aprendizaje paralelo.

## Capas del repertorio

1. **VISUAL_MEMORY:** formas y referencias observadas; no implica comprensión ni intención de autor.
2. **CASE_MEMORY:** casos y precedentes documentados; no son plantillas.
3. **ABSTRACT_ARCHITECTURAL_KNOWLEDGE:** relaciones, hipótesis, operadores y contraejemplos con provenance explícita.

## Distinciones esenciales

- `ARCHITECTURAL_SEED` no es `COMPUTATIONAL_SEED`.
- `SEED`, `PARTI`, `STRATEGY`, `FORM`, `ORGANIZATION`, `TOPOLOGY` y `CANDIDATE` cumplen roles distintos.
- `REFERENCE`, `PRECEDENT` y `ANALOGY` se recuperan con modos diferentes.
- La semejanza visual no autoriza copiar formas ni atribuir intenciones.
- `AVAILABLE`, `ACCESSIBLE` y `EXPLORED` son estados distintos del espacio de diseño.
- La composición puede analizarse; el valor estético continúa bajo juicio humano.
- `UNKNOWN` no se convierte en PASS por ausencia de fallas detectadas.

## Contenido inicial

El checkpoint contiene cinco fixtures representativos y hooks R0–R4. No se incorpora todavía una biblioteca masiva, scraping, corpus de imágenes protegido ni ingestion automática de precedentes.

La representación machine-readable vive en `client/src/components/arkiRPartiManual.ts`; ambas representaciones comparten identidad conceptual y provenance.

## Estado epistemológico

Todo contenido permanece como fuente documentada, derivación, interpretación o candidato según su etiqueta. La revisión humana es obligatoria. El Manual no canoniza conocimiento, no crea ganadores y no declara creatividad autónoma.
