# ARKI — Research Implementation Handoff v1.0

## Estado

El handoff se operacionalizó como una extensión compositiva de los contratos existentes. No se creó un segundo modelo canónico, un segundo grafo de programa, un segundo motor tipológico o un segundo motor regulatorio.

La nueva superficie conecta perfil funcional, sistemas mínimos, actividades, procesos, estados, flujos, relaciones, controles, interfaces, capacidades y requisitos funcionales. Sus vistas de organigrama, proceso, flujo, control, interfaz, zonificación y red son derivadas del mismo programa semántico.

## Disposiciones aplicadas

| Disposición | Resultado |
|---|---|
| REUSE_AS_IS | CanonicalBuildingModel, A21/S1/S2/GDI, ledger de fuentes, conciencia de ingeniería y gates de permiso |
| EXTEND | Perfil funcional, necesidad de sistemas, completitud, aprendizaje/transferencia y cobertura regulatoria |
| ADAPT | Conocimiento derivado de Neufert/Plazola y aplicabilidad temporal del RNE |
| MAP_TO_EXISTING | Actores, actividades, recursos, procesos, flujos, relaciones e issues |
| DATA_ONLY | Metadatos, hipótesis, unknowns y conocimiento profesional de fuente |
| DERIVED_VIEW | Organigrama, procesos, flujos, controles, interfaces, zonificación y red |
| DO_NOT_ADD | Arquitectura paralela, ontología de cuartos, score universal de belleza y ganador automático |

## Resultado funcional

El programa residencial de prueba ya no se representa como una lista de ambientes. Contiene sistemas funcionales con necesidad `ESSENTIAL`, varias realizaciones posibles, razones de relación, flujos con estados operativos, capacidad con base temporal, interfaces externas y unknowns explícitos. Cocina y comedor pueden compartir con condiciones; público y privado se separan como requisito relacional, no como regla geométrica universal.

La completitud se mantiene dependiente de la etapa. El programa puede estar presente y parcialmente resuelto sin afirmar que su realización espacial, regulación o ingeniería estén verificadas.

## Regulación y aprendizaje

La cobertura regulatoria distingue requisitos no evaluados de cumplimiento de proyecto. La selección temporal de reglas usa la fecha del proyecto y no una regla de “última versión” automática. La transferencia exige cambio de tipología, condiciones y no-aplicabilidad; copiar una solución produce `NOT_PROVEN`.

## Límites preservados

Neufert y Plazola continúan siendo referencias profesionales, no leyes. El RNE continúa siendo una fuente regulatoria de alcance parcial, no toda la regulación peruana ni una aprobación de licencia. Las dimensiones conceptuales, la geometría del anteproyecto y las reservas técnicas no constituyen cálculo profesional. La autoridad humana permanece obligatoria.
