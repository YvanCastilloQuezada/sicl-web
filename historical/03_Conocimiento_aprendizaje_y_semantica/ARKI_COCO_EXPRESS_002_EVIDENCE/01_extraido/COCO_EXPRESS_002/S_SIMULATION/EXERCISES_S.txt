ORACLE TRANSVERSAL
------------------
Cada registro debe contener:
  project, time, scenario, scale, units, applicability,
  provenance.source, provenance.version, provenance.evidence_refs,
  epistemic, status y value.

Reglas comprobadas:
  * SIMULATION sólo puede quedar COMPUTED, UNKNOWN o NOT_APPLICABLE.
  * OBSERVATION queda OBSERVED; FORECAST queda FORECAST.
  * INTEGRITY/HASH_MATCH no se transforma en verdad física.
  * IMPORT/IMPORTED no se transforma en fidelity ni certificación.
  * CERTIFIED, TRUTH y SIGNED son estados rechazados por este oracle.
  * Si la escala pedida no coincide, el resultado debe ser NOT_APPLICABLE.
  * La ausencia de metadatos o procedencia es un fallo, no UNKNOWN silencioso.

ADVERSARIAL — Cuatro etiquetas que no deben colapsar
-----------------------------------------------------
Propósito: impedir que la interfaz o un importador convierta estados diferentes
en una sola afirmación de verdad.

Cuatro registros del mismo proyecto P-SIM-02, con metadata completa:
  1) OBSERVATION / OBSERVED: 31.2 degC de sensor-A en junio 2029.
  2) FORECAST / FORECAST: 33.0 degC de weather-model para julio 2029.
  3) INTEGRITY / HASH_MATCH: hash abc de un artefacto de import radiance.
  4) IMPORT / IMPORTED: archivo aceptado por idf-loader.

Assertion: los cuatro registros son aceptados sólo con su semántica propia. El
hash no prueba exactitud física; import success no prueba fidelity; forecast no
es observación; observación no es simulación ni certificación.

Salida:
ADVERSARIAL PASS: observation, forecast, hash/integrity and import success stayed distinct; none became physical truth or certification.

-------------------------------------------------------

proyecto P-SIM-03, escenario occupied, receptor y geometría de habitación.

scale=building. Se conserva project/time/scenario/units/provenance y no se

FALSE ni certificación; indica que la transferencia no está demostrada.

Salida:
