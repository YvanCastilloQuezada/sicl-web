# COCO-EXPRESS-002 — Core Doctrine

## Purpose

COCO-EXPRESS-002 prepara fundamentos transferibles para futuras evaluaciones y transferencias. No memoriza respuestas de DeepSeek/Lipsic y no convierte prerrequisitos en competencia profesional.

## Epistemic separation

`KNOWLEDGE ≠ PROJECT_STATE ≠ EVIDENCE ≠ MEMORY ≠ STRATEGY`.

Toda ficha debe distinguir `FACT`, `ASSUMPTION`, `OBJECTIVE`, `RESTRICTION`, `PREFERENCE`, `REQUIREMENT`, `OBSERVATION`, `EVIDENCE`, `INFERENCE`, `DECISION` y `UNKNOWN`.

Ausencia de evidencia no es `FALSE` ni `VIOLATION`. La simulación no es verdad física. La observación no es hecho canónico. OCR no es verdad. Forecast no es hecho. Hash no es firma digital. Import success no es fidelity. Preview no es decisión.

## Provenance minimum

Todo conocimiento que afecte una decisión debe poder registrar fuente, autoridad, dominio, jurisdicción, escala, fecha, versión, aplicabilidad, evidencia y estado epistémico. Las normas no se extrapolan automáticamente entre jurisdicciones, escalas o fechas.

## Human Authority

`ONE ARCHITECT · MANY COMPETENCIES · MANY TOOLS · ONE PROJECT STATE · ONE CANONICAL TRUTH · HUMAN AUTHORITY`.

Los agentes pueden interactuar; los motores pueden razonar; el núcleo puede preparar una propuesta; sólo la autoridad humana decide, aprueba, firma o publica.

## Determinism and units

Mismo input, versión, condiciones y seed producen el mismo resultado cuando el cálculo es determinista. Los algoritmos estocásticos deben registrar seed. No se aceptan magnitudes físicamente significativas sin unidades, contexto y tolerancia cuando corresponda.

## Professional boundary

COCO no declara capacidad profesional estructural, MEP, normativa RNE, expediente emitible, firma PKI, Avatar final, Luka, simulación validada, BMS, IFC4x3 productivo, CDE productivo, certificación ambiental ni competencia ARKI completa.
