ORDEN MAESTRA A MANUS
TRANSFORMACIÓN DE MULTI JUEGOS PERÚ EN UNA MÁQUINA AUTÓNOMA DE ENTRETENIMIENTO INTERACTIVO

Manus:

A partir de este mensaje quiero que ejecutes una transformación integral de Multi Juegos Perú (MJP).

No quiero únicamente un análisis, una propuesta conceptual ni una lista de tareas.

Quiero que inspecciones el proyecto actual, determines qué puede reutilizarse, implementes la nueva arquitectura y dejes el sistema funcionando en el entorno de pruebas, manteniendo el proyecto estrictamente en modalidad virtual/demostrativa y sin habilitar dinero real.

La visión objetivo es:

MULTI JUEGOS PERÚ = una máquina autónoma de entretenimiento digital interactivo.

La TV será el escenario público.

El celular será la segunda pantalla y control personal.

La PWA/web será la interfaz individual.

El motor de juegos será el núcleo.

El avatar será el presentador digital contextual.

El Event Engine coordinará cada evento.

El Scheduler Engine construirá la programación.

El Automation Engine ejecutará las operaciones repetitivas.

El sistema de auditoría registrará todo.

Debe existir supervisión humana y capacidad de interrupción de emergencia.

3. PRIMER OBJETIVO: CREAR EL EVENT ENGINE

Este es el cambio arquitectónico principal.

No quiero que la TV dependa directamente de cada juego.

Quiero una abstracción común:

EVENT

Cada evento debe representar una instancia programada de una actividad MJP.

Ejemplo conceptual:

MJP EVENT
│
├── eventId
├── eventType
├── gameId
├── scheduledStart
├── participationOpen
├── participationClose
├── executionStart
├── executionEnd
├── status
├── rulesVersion
├── displayConfiguration
├── qrConfiguration
├── avatarScript
├── result
├── verification
├── auditTrail
└── recoveryState

Los estados deben ser explícitos.

Como mínimo:

SCHEDULED
PREPARING
OPEN
CLOSING
LOCKED
DRAWING

PUBLISHED

No implementes esto necesariamente con estos nombres si la arquitectura existente tiene una mejor solución, pero debe existir una máquina de estados equivalente y explícita.

4. EVENTOS Y JUEGOS DEBEN ESTAR SEPARADOS

Un juego define:

qué se juega.

Un evento define:

cuándo y bajo qué versión de reglas se ejecuta una instancia de ese juego.

Ejemplo:

GAME
LOT39

EVENT
MJP-2026-08-25-2000-LOT39

Esto permitirá reutilizar el mismo juego miles de veces sin duplicar su definición.
