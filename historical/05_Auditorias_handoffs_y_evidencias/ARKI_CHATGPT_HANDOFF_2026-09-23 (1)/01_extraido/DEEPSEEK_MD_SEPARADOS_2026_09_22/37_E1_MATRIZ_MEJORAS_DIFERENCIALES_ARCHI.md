# E1.9 — Matriz de mejoras diferenciales de Archi

Archi no debe limitarse a replicar pantallas. Las mejoras se deben convertir en contratos verificables.

| Diferencial | Problema que resuelve | Resultado esperado | Evidencia |
|---|---|---|---|
| Cadena paramétrica a expediente | Evita datos aislados | Parámetro → geometría → metrado → costo → 4D → documento | Prueba E2E |
| Trazabilidad de elemento | Evita pérdida entre vistas y formatos | Identidad 2D/3D/IFC/Revit | Round-trip |
| Asistencia contextual | Reduce errores de usuario | Ayuda basada en estado y fuente | Pruebas de guía |
| Fail-closed profesional | Evita falsas aprobaciones | Bloqueo explícito ante falta de evidencia | Tests de gate |
| Catálogo corporativo gobernado | Evita familias duplicadas | Familias con versión, reglas y responsable | Inventario |
| Comparación de alternativas | Evita revisar solo métricas | Cambios visuales y semánticos navegables | Comparador |
| OCR con revisión humana | Evita automatización opaca | Fuente, confianza y aprobación | Fixtures documentales |
| Mantenimiento desde el modelo | Evita perder información al construir | Activos, garantías y órdenes ligados a BIM | O-M |
| Flujo multi-especialista | Evita silos | Proponer, revisar, aprobar y auditar | Matriz de roles |

No se debe implementar un diferencial como lema. Cada uno debe recibir contrato, prueba, output y estado.
