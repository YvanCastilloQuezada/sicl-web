# ADR-003 — Identidad estable de elemento

**Estado:** Aprobado como extensión gobernada para E5 Revisado  
**Fecha:** 2026-09-23

## Decisión

Los elementos deben conservar un `ArchiElementId` estable y determinista entre ConstructionModel, SceneModel, CanvasPlanView, SceneModel3D y futuras exportaciones IFC.

El `globalId` IFC queda definido como campo de interoperabilidad futura. No se declara round-trip IFC productivo en E5.

## Reglas

- No usar `Math.random()` ni `Date.now()` para IDs críticos.
- El ID debe derivar de la identidad canónica del dominio o de una función determinista versionada.
- Un cambio geométrico no debe cambiar la identidad del elemento si el elemento lógico es el mismo.
- La desaparición y aparición de elementos debe ser detectable por comparación de snapshots.
- La asignación de `globalId` deberá tener su propio contrato y pruebas antes del adaptador IFC.

## Consecuencia

La selección, comparación, trazabilidad y exportación futura pueden referirse al mismo elemento sin duplicar entidades.
