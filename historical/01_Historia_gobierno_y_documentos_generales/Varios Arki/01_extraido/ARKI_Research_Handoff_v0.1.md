# ARKI --- RESEARCH HANDOFF v0.1

**Fecha de consolidación:** 2026-09-19\
**Estado:** `RESEARCH CONSOLIDATION / IMPLEMENTATION NOT AUTHORIZED`

## 1. Propósito

Este handoff congela el conocimiento investigado y estructurado hasta el
frente **L23 --- Site + Landscape**, para que el trabajo posterior
continúe desde evidencia ya reunida y no vuelva a investigar lo mismo.

Regla operativa:

`RESEARCH ONCE → STORE RESULT IN MATRIX → REUSE VERIFIED RESEARCH → RESEARCH ONLY THE DELTA`

La matriz Excel asociada es el registro estructurado principal.

## 2. División permanente de responsabilidades

-   **ChatGPT:** investigación externa, arquitectura del conocimiento,
    dirección curricular, síntesis y preparación de órdenes.
-   **Manus:** programación e implementación, únicamente cuando exista
    autorización expresa.
-   No enviar a Manus a investigar bibliografía, universidades,
    precedentes, normativa o estado del arte salvo orden expresa del
    Product Owner.
-   Este handoff **no autoriza programación**.

## 3. Contrato pedagógico vigente

La Escuela de Arquitectura de ARKI trabaja con:

`PRINCIPLE → EXPLANATION → PRACTICE → EVALUATION → CORRECTION → TRANSFER`

Después de dominar varios principios:

`A + B + C → INTEGRATED PRACTICE → EVALUATION → TRANSFER`

Luego aumenta la complejidad y después la escala.

`MICRO → MACRO` no es una línea rígida; funciona como una espiral: un
principio reaparece a escalas mayores y ARKI debe demostrar qué se
conserva, qué cambia y cuándo deja de ser aplicable.

## 4. Estado curricular consolidado

### L00--L08 --- Fundamentos y programación

-   L00: punto, línea, plano, volumen, forma, espacio, límites,
    aberturas, organización, circulación, proporción, escala y orden.
-   L01: cuerpo, antropometría, variabilidad humana, postura,
    movimiento, alcance y actividad envelope.
-   L02: actividad. `ROOM NAME ≠ ACTIVITY MODEL`.
-   L03: objetos/equipamiento. `OBJECT FOOTPRINT ≠ USE ENVELOPE`.
-   L04: espacio habitable.
    `PHYSICAL FIT ≠ FUNCTIONAL FIT ≠ HABITABILITY ≠ ARCHITECTURAL QUALITY`.
-   L05: relaciones espaciales, umbral, secuencia, privacidad, acceso y
    conflictos.
-   L06: organización/composición.
    `FORM ≠ ORGANIZATION ≠ CIRCULATION ≠ SECTION ≠ VOID ≠ SUPPORT`.
-   L07: programación. `NEED ≠ SOLUTION`; separar objetivos, hechos,
    supuestos, requisitos, preferencias, restricciones y decisiones.
-   L08: síntesis programa→topología. `TOPOLOGY BEFORE COORDINATES`.

### L09--L12 --- Primera arquitectura y transferencia tipológica

-   L09: unidades funcionales: puesto de trabajo, descanso,
    almacenamiento, cocina, baño, etc.
-   L10: arquitectura pequeña como primera integración completa.
-   L11: vivienda como sistema de habitación, no como lista de
    habitaciones.
-   L12: transferencia a pequeño no residencial: oficina, comercio,
    café, aula, taller, consulta, pabellón.

Tipología se estudia como:

`USERS → ACTIVITIES → EQUIPMENT → USE ENVELOPES → RELATIONSHIPS → FLOWS → CONFLICTS → TECHNICAL AWARENESS → DESIGN QUESTIONS`

No como plano a copiar.

### L13--L19 --- El edificio como sistema físico

-   L13: elementos del edificio; distinguir significado arquitectónico,
    realización física y assembly constructivo.
-   L14: materiales. `MATERIAL ≠ TEXTURE MAP`.
-   L15: assemblies. `WALL ≠ ONE MATERIAL`.
-   L16: envolvente como mediación interior/exterior.
-   L17: ambiente: luz, aire, térmico, acústica, humedad. Intención
    arquitectónica ≠ desempeño verificado.
-   L18: servicios. El edificio requiere espacio para sistemas
    invisibles; awareness/coordinación ≠ cálculo.
-   L19: edificio multinivel. `SECTION IS DESIGN`.

Ingeniería permanece dividida en:

1.  `LEVEL 1 — ENGINEERING AWARENESS`
2.  `LEVEL 2 — ENGINEERING DESIGN INTELLIGENCE`
3.  `LEVEL 3 — VERIFIED ENGINEERING COMPUTATION`

No inventar dimensiones estructurales, caudales, cargas, ductos,
tuberías, iluminación, energía ni otros resultados de Level 3.

### L20--L21 --- Edificio intermedio y complejo

-   Múltiples familias de usuarios.
-   `FLOW ≠ CIRCULATION SPACE`.
-   Flujos de personas, servicio, materiales, residuos, emergencia,
    etc., sólo cuando correspondan.
-   Tiempo y ocupación pasan a formar parte del programa.
-   `FLEXIBILITY ≠ OPEN PLAN`.
-   Programa complejo requiere grafos/capas de relación funcional,
    acceso, circulación, privacidad, servicio, operación, ambiente y
    dependencia técnica.
-   `COORDINATE ≠ CALCULATE`.
-   Arquitectura compleja = negociación entre requisitos válidos y a
    veces contradictorios, no optimización automática de una sola
    variable.

### L22--L23 --- Campus, sitio y paisaje

-   `SPACE BETWEEN BUILDINGS ≠ LEFTOVER SPACE`.
-   Un campus es edificio + espacio exterior + circulación + paisaje +
    infraestructura + relaciones.
-   `SITE ≠ PROPERTY BOUNDARY`.
-   Capas iniciales: legal, topografía, hidrología, suelo/geología,
    clima, sol, viento, vegetación/ecología, preexistencias,
    infraestructura, accesos, movimiento, vistas, ruido, adyacencias,
    cultura/historia, contexto urbano, riesgos y oportunidades.
-   `SITE ANALYSIS ≠ SITE DESIGN`.
-   `DATA ≠ DECISION`.
-   Evidencia del sitio debe seguir:
    `EVIDENCE → INTERPRETATION → DESIGN QUESTION → STRATEGY → MOVE`.
-   Topografía y agua participan en el diseño; no se inventan cálculos.
-   `LANDSCAPE ≠ ADD TREES`.
-   Edificio, paisaje, infraestructura y espacio abierto deben
    coordinarse.
