class EpistemicState(str, Enum):

4.4 SufficiencyStatus
python
class SufficiencyStatus(str, Enum):
    SUFFICIENT               = "SUFFICIENT"
    CONDITIONALLY_SUFFICIENT = "CONDITIONALLY_SUFFICIENT"  # solo faltan non-blocking o hay ASSUMED aceptable
    INSUFFICIENT             = "INSUFFICIENT"              # falta algún blocking
    CONFLICTING              = "CONFLICTING"                # CONFLICTING en algún blocking
    UNKNOWN                  = "UNKNOWN"                    # snapshot malformado, no interpretable
Orden de precedencia para resolver el estado global (fail-closed):

Snapshot malformado → UNKNOWN.

Algún campo blocking en CONFLICTING → CONFLICTING.

Algún campo blocking en estado no aceptado → INSUFFICIENT.

Algún campo blocking en ASSUMED (aceptado por perfil) → CONDITIONALLY_SUFFICIENT.

Solo faltan non-blocking o están aceptables → CONDITIONALLY_SUFFICIENT.

Todo blocking aceptable con evidencia → SUFFICIENT.

5. MULTIESCALA / JURISDICCIÓN / EVIDENCIA
Cada FieldRequirement puede restringirse a scales. Un campo puede estar KNOWN a escala BUILDING y MISSING a escala SITE.

Cada FieldRequirement puede declarar jurisdictions. RNE-A010 aplica a Perú; NFPA-101 a EEUU. A-002 no inventa jurisdicciones.

requires_evidence=True significa: aunque el campo esté KNOWN, si no hay evidence_refs, el estado efectivo baja a OBSERVED (fail-closed).

6. CONFLICTO — PRESERVACIÓN
Si dos fuentes declaran valores incompatibles para el mismo campo:

El estado del campo es CONFLICTING.

El reporte preserva ambos valores en conflicts.

No se elige uno silenciosamente.

Se genera HumanQuestion de arbitraje.

Si el campo es blocking, el estado global pasa a CONFLICTING (nunca a SUFFICIENT).

Esto es CONFLICT MUST REMAIN VISIBLE del Core, aplicado al input.
