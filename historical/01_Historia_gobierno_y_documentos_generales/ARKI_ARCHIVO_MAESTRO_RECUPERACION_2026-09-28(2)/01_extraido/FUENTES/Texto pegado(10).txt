3.9 SufficiencyStatus
python
class SufficiencyStatus(str, Enum):
    SUFFICIENT               = "SUFFICIENT"
    CONDITIONALLY_SUFFICIENT = "CONDITIONALLY_SUFFICIENT"
    INSUFFICIENT             = "INSUFFICIENT"
    CONFLICTING              = "CONFLICTING"
    UNKNOWN                  = "UNKNOWN"
Precedencia (fail-closed):

Snapshot malformado → UNKNOWN

Campo blocking CONFLICTING → CONFLICTING

Campo blocking en estado efectivo no aceptado → INSUFFICIENT

Campo blocking en ASSUMED aceptado por perfil → CONDITIONALLY_SUFFICIENT

Solo falta non-blocking o hay conflictos non-blocking → CONDITIONALLY_SUFFICIENT

Todo blocking aceptable → SUFFICIENT

RT-05: conflicto en non-blocking no degrada automáticamente el estado global. Se preserva en assessments[i].conflicts y genera HumanQuestion. Si el perfil lo permite, la operación puede continuar en CONDITIONALLY_SUFFICIENT.

4. Reglas de comportamiento
4.1 Determinismo
Mismo input + misma operación + mismo perfil → mismo canonical_dict() byte-a-byte.

evaluation_id calculado determinísticamente:

text
sha256(project_id + "|" + snapshot_fingerprint + "|" +
       profile_id + "@" + profile_version + "|" +
       operation.value)
Sin Math.random, sin Date.now, sin red, sin providers.

Orden de assessments = orden del perfil. human_questions ordenadas por prioridad.

4.2 Fail-closed
Snapshot None / no-dict / malformado → UNKNOWN.

Si proceed_allowed = False, el gate rechaza incluso si alguien quiere continuar.

Si evaluation_id no coincide con el contexto del gate → rechazar.

4.3 No invención
No sugiere valores.

No infiere campos.

No propone aplicabilidad.

No valida que la evidencia sea semánticamente suficiente.

4.4 Read-only
No modifica el snapshot.

No escribe al DerivationLedger.

No genera eventos en el Core.

No invoca H-001..H-005.

4.5 Identidad y anti-replay (RT-08, RT-09)
Todo reporte tiene evaluation_id, project_id, snapshot_fingerprint, profile_id@version, operation.

El gate revalida cada dimensión contra el contexto actual. Si alguna no coincide → rechazo.

Es imposible reutilizar un reporte de otro proyecto, otro snapshot, otro perfil u otra operación.

class RecomputationEntryPoint:
    """Única entrada oficial para recomputación integrada A-002 → GATE → H-005."""
    @classmethod
    def run(cls, *, project_id, snapshot, operation, profile,
            current_refs, ledger, registry) -> IntegrationResult:
        report = check_input_sufficiency(snapshot, operation, profile=profile)
        decision = gate_recomputation(report, project_id=..., snapshot=..., ...)
        if decision != GateDecision.ALLOW:

        # invocar H-005 como siempre

Límite explícito del contrato:

H-005 puede seguir siendo llamado directamente por cualquier caller que ignore el RecomputationEntryPoint.

A-002 no puede impedirlo sin modificar H-005.

El contrato declara que llamar a H-005 sin pasar por RecomputationEntryPoint es una violación de política, no una violación técnica detectable en runtime.

Test adversarial obligatorio: test_h005_bypass_boundary_documented_but_enforceable_via_entrypoint — verifica que:

RecomputationEntryPoint.run rechaza cuando A-002 dice BLOCK.

RecomputationEntryPoint.run ejecuta cuando A-002 dice ALLOW.

La documentación del módulo declara la política de frontera.

Enforcement duro (bloquear H-005 crudo) requiere modificar H-005 → fuera de scope de A-002. Se documenta como deuda futura.

6. Matriz adversarial (RT-10)
Sustituye "15 tests" por 8 familias. Mínimo 1 test por familia; recomendado 2.

Familia	Casos obligatorios
F1 — Estructura malformada	None, str, int, list, dict con tipos inválidos, NaN, inf, whitespace-only
F2 — Epistémica forjada	declared_state=KNOWN sin evidencia; KNOWN con evidence_refs=(); KNOWN con hash inválido
F3 — Evidencia forjada	evidence_refs con id vacío, hash corto, source vacío, duplicados, declared_supports_field inconsistente
F4 — Identidad	Reporte de otro proyecto; otro snapshot; otro perfil; otra versión de perfil; otra operación; reporte stale
F5 — Escala y jurisdicción	Campo presente en escala A pero requerido en B; jurisdiction_id desconocida; aplicabilidad UNKNOWN cuando se exige; aplicabilidad CONFLICTING
F6 — Política	Intento de modificar allow_conditional; intento de promover CONDITIONALLY_SUFFICIENT a SUFFICIENT; intento de saltar bloqueo
F7 — Orden y determinismo	Mismo input en distinto orden → canonical_dict() idéntico; evaluation_id estable
F8 — Human Authority	Intento de bypass del gate; intento de usar reporte sin firma para desbloquear operación crítica
Total mínimo: 8 tests. Recomendado: 16 (2 por familia).
